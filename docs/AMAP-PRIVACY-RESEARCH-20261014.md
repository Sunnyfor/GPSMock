# 高德地图隐私授权核验

核验日期：2026-10-14（Asia/Shanghai）。本文是工程决策依据，不是法律意见或上架合规认证。
适用依赖：`com.amap.api:3dmap-location-search:11.3.100_loc11.3.000_sea9.8.1`，即地图、定位、搜索合包。
本次仅研究政策；未修改 App 隐私逻辑、定位权限或 SDK 配置。

## 结论

不必每次打开都重复弹同一份隐私政策，但不能做成“安装后点过一次就永久有效”。
应在首次打开产品时展示 App 自身隐私政策并取得明确同意；以后依据有效、未撤回且覆盖当前处理范围的授权记录恢复状态。
这是依据下述官方要求形成的工程方案，官方没有指定必须采用某种本地存储，也没有规定同一授权每次冷启动都重新弹窗。

合包依赖的存在不等于已经启用所有功能；披露需覆盖实际调用、权限和数据处理，不能照抄无关字段，也不能仅因定位类未被主动调用就忽略合包中实际发生的数据处理。高德要求参考合包整体披露并结合真实采集范围。[合包披露说明](https://developer.amap.com/api/compliance-center/check-and-reference/sdkhgsy)

## “当前位置居中”的边界

App 隐私同意、SDK 合规状态与系统定位权限是三个不同门禁；同意地图隐私政策不等于系统允许读取设备位置。
Android 将页面可见时的一次定位归为前台定位，并要求兼容用户仅授予大致位置；此用途没有必要申请后台定位。[Android 定位权限](https://developer.android.com/develop/sensors-and-location/location/permissions)

推荐先展示用途“读取一次设备位置，仅用于地图居中”，取得适用的定位/第三方处理授权，再按需申请系统权限；没有许可或定位失败时仍保留地图选点、手输、收藏及模拟控制。
默认进入地图可在有效授权和权限已经具备时尝试一次定位；否则显示“定位到我”入口，不反复强制申请。
新增精确位置处理建议按敏感信息风险单独评估、显著告知，不用系统权限弹窗替代业务层的充分告知。

若使用高德定位，初始化后可能保留系统信息监听；一次定位结束应释放定位客户端，不仅停止定位。[高德定位资源释放说明](https://lbs.amap.com/api/compliance-center/check-and-reference/sdkhgsy)
若未来上架 Google Play，当前 Android 文档对 target API 37 且仅需会话定位的应用另有 location button 政策提示；需按实际分发渠道另行核验，不能据此宣称所有 Android 安装都强制采用该按钮。[Android 定位权限](https://developer.android.com/develop/sensors-and-location/location/permissions)

## 推荐授权记录与恢复策略

以下是待实施的工程建议，不是高德指定的存储协议：

- 本地记录明确选择、告知版本、SDK 政策版本、功能授权范围与同意时间；不为证明点击额外采集设备标识或当前位置。应用重启先读记录，再决定门禁。
- 同意有效且范围未变：不重复弹窗。拒绝：保留离线能力，不在无关操作中持续索取同意；用户主动启用在线功能时允许重新选择。
- 撤回：立即关闭相关在线能力、取消请求并释放 SDK 资源，更新持久记录；撤回后的重新使用需再次授权。设备权限撤销也必须动态检查。
- 清除应用数据或无有效记录：重新告知。覆盖升级可保留有效记录；不能用“安装次数”推断同意是否存在。
- 为让重装和换机不静默继承旧授权，建议将同意记录排除出云备份、设备迁移及适用的跨平台迁移，或放在不备份存储并核验实际设备行为。

Android 默认备份包含 SharedPreferences，并可能在安装后恢复；`allowBackup=false` 在部分厂商设备上不能单独保证禁止设备间迁移，应结合版本化备份规则验证。[Android 自动备份](https://developer.android.com/identity/data/autobackup)

## 实施后应验证

首次打开 / 拒绝 / 重启 / 同意后重启 / 撤回 / 清除数据 / 覆盖升级 / 备份恢复；同时检查未授权前没有地图、搜索、定位客户端初始化或网络采集。
一次定位需覆盖拒绝、大致位置、权限被系统收回、超时及资源释放；当前位置居中不得自动启动模拟会话。
